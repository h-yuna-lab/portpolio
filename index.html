측정 결과·조건 ↗ 벤치마크 커밋 ↗ 통합시험 커밋 ↗

Team project 2026.08 — 09

HydroTwin

프로젝트 완료

센서 데이터에서 모델 판단까지,
이상 상태를 설명하다.

3대 유압 설비의 17개 센서 데이터를 분석하고 부품 상태를 보여주는 디지털 트윈 프로젝트입니다. 저는 데이터 분석·전처리, 분류 모델 학습·평가·SHAP을 담당하고, 대시보드 레이아웃과 이상 상세 팝업을 개선했습니다.

팀 프로젝트 실행 화면. 제 UI 기여는 아래 커밋에서 확인할 수 있습니다.

TEAM

WHAT I DID

담당 작업

분석부터 설명 가능한 화면까지

01 / DATA & EDA

학습 전에 데이터의 구조부터 확인

UCI 유압 센서 데이터와 상태 라벨을 분석하고 EDA 노트북을 정리했습니다. 원본 검증, 센서 평균 특징 추출, 공통 cycle_id 기반 분할을 통합 파이프라인에 연결해 같은 사이클이 학습·검증·테스트에 섞이지 않도록 검사했습니다.

담당 문서 ↗EDA 커밋 ↗파이프라인 커밋 ↗

02 / MODEL & EXPLANATION

성능과 판단 근거를 함께 평가

RandomForest·LightGBM 모델 비교와 학습·분할 로직을 작성하고 Accuracy·Macro F1·혼동행렬·SHAP 분석을 정리했습니다. 학습·평가·설명 실행 모듈을 추가했으며, 이후 RandomForest 모델 번들로 전환하는 변경도 수행했습니다.

학습·분할 커밋 ↗평가·SHAP 커밋 ↗RF 전환 커밋 ↗

03 / DASHBOARD UI

정보를 읽기 쉬운 관제 화면

대시보드의 레이아웃과 디자인을 개선하고 사이드바 너비 조절 기능을 추가했습니다. 화면에서 설비·센서 정보를 확인할 때 각 영역의 크기를 조절할 수 있도록 작업했습니다.

레이아웃 커밋 ↗사이드바 커밋 ↗

04 / ANOMALY DETAIL

정상 복귀 뒤에도 남아 있는 이상 기록

AI 이상 상세 팝업에 상위 영향 센서 3개의 그래프와 정상 범위 비교를 추가했습니다. 팝업을 연 시점부터 이상 구간을 기록하고 정상 복귀 시 기록을 종료하되, 팝업을 닫기 전까지 마지막 이상 내용과 그래프를 유지하도록 개선했습니다.

상세 팝업 커밋 ↗센서 분석 개선 ↗기록 유지 커밋 ↗

DESIGN DECISION

이상이 사라져도,
판단 근거는 확인할 수 있게.

실시간 센서가 정상으로 돌아왔다고 팝업까지 갱신하면, 방금 발생한 이상을 분석할 근거가 사라집니다. 이상 구간의 기록 종료와 팝업 데이터 삭제를 분리해 사용자가 확인을 마칠 때까지 내용을 유지했습니다.

SHAP은 모델 판단에 영향을 준 센서를 설명합니다. 물리적인 고장 원인을 확정하거나 잔여수명을 예측하는 결과로 표현하지 않았습니다.
